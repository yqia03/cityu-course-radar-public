## 公开范围

公开仓库以经过审查的新快照开始，不复制私有提交历史。发布项目代码、迁移、测试、CI、公开课程快照、简短外部评价摘要及归属。用户评价、账号、积分账本、上传资料、密钥、数据库备份、生产证据截图和工作区文件均不随源码发布。

项目自有代码沿用 MIT。官方课程材料、外部原帖和第三方组件保留各自权利，见 [第三方说明](../THIRD_PARTY_NOTICES.md)。源码不包含学校试卷 PDF、原帖图片组或翻译模型权重；公开来源链接删除分享令牌和追踪参数后可能需要读者在原平台正常登录查看。

## 本地开发与独立部署

按 [README](../README.md) 安装并运行本地 D1。公开 `wrangler.json` 不含生产账户 ID，数据库 ID 为占位符，站点 origin 为 `https://your-domain.example`；本地模拟器不使用这些值访问远端。部署前创建自己的 D1 和私有 R2，替换相应绑定和 origin，配置自己的 Google OAuth 与管理员，并按 [部署手册](cloudflare-deployment.md) 和 [资料库运维](materials-operations.md) 验收。不要使用其他人的生产凭据，不要将上传对象公开。上传默认受限，必须核对自己的免费额度与开关；本项目不自动开通计费服务。

## 维护者发布流程

1. 在私有开发仓库完成修改、审查、测试并提交。
2. 运行 `node scripts/export-public.mjs <尚不存在的新目录>`。工具只读取当前 HEAD 的已提交文件，以白名单过滤路径，替换生产配置，删除来源链接令牌；不会复制 Git 历史、忽略文件或未跟踪文件，也不会覆盖已存在目录。
3. 检查导出差异、许可证、敏感信息和来源归属；在导出目录运行 README 的全部验证。脚本仅提供筛选，不能替代人工审查。
4. 首次发布在导出目录初始化新的 Git 仓库；之后以公开仓库最新 main 为基线，复制审查后的变更并正常提交推送。保留公开提交历史，不强推，不把私有仓库直接镜像到公开远端。
5. 核验匿名访问及公开 CI。公开 CI 不配置生产凭据，不承担生产部署；生产仍从经过验证的私有工作分支部署。

公开仓库的 Star 入口只打开 GitHub 项目页，不会代替访客点赞或收集 GitHub 登录信息。
